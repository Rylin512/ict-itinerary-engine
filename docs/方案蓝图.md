## 0. 30 秒结论

1. **选题成立，但"路线规划"本身不值钱**。携程/飞猪/小红书/ChatGPT 都能排一条线。评委真正会追问的是："LLM 已经能做，你为什么还要做？"
2. 你的答案应该是：**把"能看的行程"做成"能执行的行程"**——用**约束求解器**保证时间窗、交通、体力、预算真的可行，用**大模型**做理解与表达，用**鸿蒙一次开发多端**做手机在路上看、PC 在桌前改。
3. 技术主线：**华为云 MaaS（盘古/DeepSeek）+ 华为云 OptVerse 天筹求解器 + FunctionGraph + 鸿蒙 ArkTS 多端**。这条线既满足赛题一"必须用华为云"，又把"AI 应用"落到可验证的工程上。
4. 时间主线：**11/6 前出方案 + PPT + 3 分钟视频**（多数学校校赛节点），**11/30 前完成官网报名**，代码在方案之后补齐。别反过来。

## 1. 赛题解读：评委在打什么分

### 1.1 硬性约束（赛题一）

| 项 | 要求 | 对你的影响 |
|---|---|---|
| 技术 | 基于**华为云产品**打造 AI 创新应用 | 华为云必须是"骨架"，不能只在最后调一次 API |
| 形式 | 创新项目，方案设计 + 作品开发 + 答辩 | 文档、演示、代码三者都要 |
| 组队 | 3 名学生 + 1 名指导教师，同校 | 现在就要定人 |
| 赛制 | 初赛 → 中国总决赛 → 全球总决赛 | 初赛材料决定生死 |

### 1.2 软性评分（官方未公开细则，按历年评审惯例判断）

- **创新性**：是不是新问题、新解法，还是"又一个 ChatGPT 套壳"
- **技术含量与华为技术深度**：用了几个华为云服务？是调用还是深度使用？有没有自研模块？
- **完成度**：现场能不能跑通、有没有真实数据、有没有用户
- **落地价值**：谁付钱、市场规模、可复制性
- **答辩表达**：3 分钟能不能讲清楚

> 结论：**"华为技术深度"和"完成度"是学生队最容易拿分、也最容易丢分的地方。** 少堆概念，多做一个能现场跑的真链路。

### 1.3 你这个题的真实风险

| 风险 | 严重度 | 应对 |

## 2. 产品定位：从"排路线"升级为"行程决策智能体"

### 2.1 一句话

> **"说一句话：下周成都 3 天，带爸妈，不想太累，预算 3000——它先给你本地景点挑；你勾完，它排出每一段怎么走：坐几号线、从哪个口出、换几路车、往哪个方向、哪站下、步行多少米，每个点待多久。"**

### 2.2 目标用户与场景

- **主场景**：2—6 人自由行，行前 1—7 天做攻略（决策成本最高、最容易吵架）
- **次场景**：行程中被扰动（下雨、排队、闭馆、同行人累了）需要当场改
- **B 端想象空间**：县域文旅 / 景区 / 酒店礼宾的"定制行程"工具（答辩用来讲商业闭环）

### 2.3 差异化五板斧（答辩就讲这五条）

1. **可执行**：不是文本，是带时间窗、交通时长、营业时间、预约要求的可行解；不可行会明确告诉你"冲突在哪、怎么改"。
2. **可解释**：每个安排都给"为什么放这里"（省 40 分钟车程 / 避开 14 点人流 / 顺路吃午饭），并给备选。
3. **可重规划**：扰动后做**局部修复**而不是整份重排，秒级返回，已有安排尽量不动。
4. **多端一致**：同一份行程，手机端是"跟着走"的卡片流，PC 端是"排布+对比"的三栏工作台，鸿蒙跨端接续。
5. **选点即算代价**：勾一个点，立刻告诉你"当天交通 +38 分钟、步行 +1.2km、和另一个点二选一"。小红书给的是地点清单，你给的是**选择的代价**——这是最难抄的一招。

### 2.4 功能范围（砍到能做完）

**P0（必须，初赛前跑通）**
- 自然语言需求输入 → 结构化槽位（城市/天数/预算/同行人/兴趣/节奏/忌口）
- 景点推荐：按兴趣/距离/开放时间分桶（必去 / 顺路 / 小众），支持勾选
- 行程生成：逐日 POI 排序 + 时间窗 + 交通时长 + 用餐 + 住宿区域建议
- **出口级换乘描述**：地铁几号线、往哪个方向、哪站换乘、哪个口出、步行多少米、公交几路
- **选点即算边际成本**：勾选/取消瞬间返回 时间 / 步行 / 费用 变化
- 地图可视化 + 时间轴（手机单列 / PC 三栏）
- 一句话调整："太累了" / "第二天下雨" / "加一个博物馆" → 重排
- 行程导出（长图/链接分享）
- 账号 + 云端保存（换端能接着改）

**P1（有时间就做，答辩加分）**
- 多人偏好录入与冲突消解（投票 + 折中方案）
- 实时扰动：天气 / 闭馆 / 排队时长
- 拍照识别景点 → 加入行程（多模态，展示华为云视觉能力）
- 预算透视（门票/餐饮/交通/住宿拆分，超支预警）

**P2（只写进 PPT，不做）**
- 语音导游、AR 实景导航、B 端运营后台、多语言出境游

> 明确"不做"和"要做"一样重要：3 人队 8 周，P0 全绿 > P0 半绿 + P1 一堆。

## 3. 技术架构

### 3.1 总体链路

```
┌──────────────────────── 端（鸿蒙 ArkTS，一次开发多端部署）────────────────────────┐
│ 手机/折叠屏        平板             PC / 2in1                                        │
│ 单列卡片流     双栏(地图+列表)     三栏(需求|行程|地图)  ← 同一套代码 + 响应式断点     │
└───────────────────────────────────┬─────────────────────────────────────────────────┘
                                    │ HTTPS / 华为账号登录（Auth）
┌───────────────────────────────────▼─────────────────────────────────────────────────┐
│ 华为云 API 网关 APIG（鉴权、限流、防刷）                                              │
├──────────────────────────────────────────────────────────────────────────────────────┤
│ FunctionGraph 函数（Python/Node，无服务器，按需伸缩）                                  │
│  ① 需求解析   ② 候选召回   ③ 组合优化   ④ 行程生成   ⑤ 规则校验   ⑥ 重规划            │
├───────────────┬──────────────────┬──────────────────┬───────────────────────────────┤
│ ModelArts     │ OptVerse 天筹     │ RDS for MySQL /  │ OBS 对象存储                  │
│ Studio (MaaS) │ 求解器（VRP/TSP） │ GaussDB          │ （行程长图、用户图片）         │
│ 盘古 / DeepSeek│ 带时间窗约束     │ POI/行程/用户     │ + 内容审核 Moderation          │
└───────────────┴──────────────────┴──────────────────┴───────────────────────────────┘
                     │  可选：KooMap（地图数据/影像）、CES（监控告警）、LTS（日志）
```

### 3.2 为什么不能让 LLM 直接排行程

这是答辩最容易被问、也最能体现技术水平的一点，建议做成一张对比页：

| | 纯 LLM 排 | LLM + 求解器 |
|---|---|---|
| 时间可行性 | 常出现"10:00 到 A，10:15 到 5 公里外的 B" | 时间窗 + 路段时长硬约束 |
| 营业/闭馆 | 会编造开放时间 | 用 POI 事实表过滤 |
| 可复现 | 每次结果不同 | 同输入同输出，可回归测试 |
| 可解释 | "我觉得这样比较好" | 给目标函数与约束松弛量 |
| 改动成本 | 重排整份 | 局部修复，保留已确认安排 |

**结论话术**："LLM 负责'听懂人话'和'说人话'，求解器负责'算得对'。"

### 3.3 AI 流水线（7 步，每步都能单独演示）

1. **需求解析**：LLM + JSON Schema 强约束，输出槽位；缺失项主动追问 1 轮。
2. **候选召回**：POI 库向量检索（RAG）+ 规则过滤（距离、评分、营业、预算档位）。
3. **候选打分**：兴趣匹配度、热度、季节适配、与已选点的协同（同区域加分）。
4. **组合优化**：把"每天选若干点 + 排序 + 满足时间窗"建模成**带时间窗的团队定向问题/VRP**，交 OptVerse 求解；无解则按优先级松弛（先舍低分点，再放宽时长）。
5. **行程叙事**：LLM 只允许引用给定 POI 事实生成文案/理由/贴士，禁止新增事实。
6. **规则校验**：时间冲突、超预算、闭馆、跨区折返、体力上限 → 不通过回第 4 步。
7. **解释与备选**：输出主方案 + 2 个变体（轻松版/紧凑版/省钱版），带差异说明。

### 3.4 核心数据模型（先定 schema，再写代码）

```
POI(id, name, city, lat, lng, category, open_hours[], suggested_minutes,
    ticket_price, rating, tags[], source, updated_at)
Trip(id, user_id, city, days, budget, party(人群/人数), pace, interests[],
     constraints[], status, version)
DayPlan(trip_id, day_index, items[OrderedItem], lodging_area, notes)
OrderedItem(poi_id, arrive, leave, transport_from_prev{mode,minutes,km}, reason, alternates[])
Leg(...)  // 距离矩阵可预计算缓存，省调用费
User(id, prefs, history, devices[])
```

**关键工程决策**：`POI 表 + 距离矩阵缓存 + 行程版本号`。有这三样，重规划和多端同步都会简单很多。

### 3.5 华为云选型与成本

| 服务 | 用途 | 备注 |
|---|---|---|
| ModelArts Studio（MaaS） | 盘古 / DeepSeek 推理 | 按 token 计费；先领大赛代金券 |
| OptVerse 天筹求解器 | 路径/排程优化 | 华为自研，CVRP 国际赛事冠军，**差异化核心** |
| FunctionGraph | 全部业务函数 | 免费额度足够 demo，免运维 |
| APIG | 统一入口、鉴权限流 | 演示"工程规范" |
| RDS for MySQL | POI / 行程 / 用户 | 最小规格即可，或用 GaussDB |
| OBS + Moderation | 图片与分享长图、UGC 审核 | 合规加分项 |
| KooMap | 地图数据/影像（可选） | 能力需按区域申请，**不要**在答辩里说"自建地图" |
| CES + LTS | 监控与日志 | 顺手做，答辩可放一张"线上运行"截图 |

> 预算参考：学生 demo 量级，MaaS + 数据库 + 函数计算，**每月数百元**；用代金券基本可覆盖。**别开包年包月。**

### 3.6 地图与数据（最容易踩坑）

- **底图/路网/POI**：用有甲级测绘资质的商用地图开放平台（高德/百度/腾讯），或学校已有授权数据。**自采 POI 只做补充，且标注来源。**
- **距离矩阵**：批量调用 + 本地缓存，避免演示时超时/超配额。
- **开放数据**：优先用当地文旅局公开数据、博物馆/景区官网开放时间（可写进"数据合规"页，评委很吃这套）。
- **演示城市只做 1 个**（建议成都/西安/苏州），做深 300—500 个 POI，比 10 个城市各 20 个强得多。

### 3.7 单段路径与出口级数据：边界在哪

一张表说清"谁负责什么"，这是答辩必问：

| 能力 | 谁提供 | 我们的工作 |
|---|---|---|
| 单段步行/公交/地铁方案（线路、方向、上下车站、耗时、票价） | 地图开放平台路径规划 API | 批量预计算 + 缓存 + 结果校验 |
| 地铁出口（A/B/C 口）与站内换乘路径 | 地图 POI「出入口」+ 站内图 | **自建出口库**（演示城市 10—20 个站即可） |
| 景点开放时间 / 门票 / 预约 | 景区官网、官方公众号 | 人工录入 + 来源标注（合规加分） |
| 一天怎么排、每个点待多久、时间够不够 | **没有现成服务** | **自研编排引擎（求解器）** |
| 怎么讲给用户听 | — | LLM 转述结构化事实，禁止新增地点 |

> 一句话：**导航可以买，编排必须自研。** 这恰好落在赛题一"用华为云做 AI 应用"上——华为云负责编排、AI、存储与调度，地图开放平台只作为事实源。

建模、约束清单、行程 JSON、时间估算、验收标准见 [技术设计-行程编排.md](技术设计-行程编排.md)。

## 4. 多端策略：三选一，别摇摆

| 方案 | 覆盖 手机+桌面 | 学习成本 | 华为生态加分 | 建议 |
|---|---|---|---|---|
| **A. 鸿蒙原生 ArkTS（推荐）** | 手机/平板/PC 2in1，一套代码 + 响应式断点 | 中（会 TS 就上手） | **最强**，直接对应"一次开发多端部署" | 3 人里有 1 人肯投入 2 周就选它 |
| B. Flutter / uni-app + 华为云 | 手机+桌面（Flutter desktop / H5） | 低—中 | 一般（只体现华为云） | 团队零鸿蒙经验、时间只剩 4 周时选 |
| C. Web / PWA | 浏览器全平台 | 最低 | 弱，易被当"套壳网页" | 只做**原型验证**和视频素材，不做最终交付 |

**推荐路径**：先用 C 做交互原型（1—2 天，跑通算法与体验），再迁到 A 交付。原型还能直接当 3 分钟视频的分镜素材。

**鸿蒙多端要点**
- DevEco Studio 新建工程勾选 `phone / tablet / 2in1`，用**断点（sm/md/lg）+ 栅格**做一次开发多端部署，别写三套页面。
- 手机端：底部导航 + 单列卡片；PC 端：左侧需求栏 + 中间行程 + 右侧地图，支持拖拽调整顺序。
- 加分项：**跨端接续**（手机上看到一半，PC 上接着改）、服务卡片（桌面卡片显示今日行程）、碰一碰分享。
- 有真机最好；没有就用模拟器 2in1 + 平板，**提前录屏**防现场翻车。

## 6. 答辩与 3 分钟视频脚本

| 时间 | 画面 | 台词要点 |
|---|---|---|
| 0:00—0:20 | 三张真实截图：Excel 攻略、聊天记录吵架、景区门口排队 | "做攻略 6 小时，现场全作废" |
| 0:20—0:30 | 产品一句话 | "你说想怎么玩，它告诉你每一段怎么走" |
| 0:30—1:10 | 输入需求 → 景点推荐 → 勾选（展示边际成本跳动） | "选这个点，当天多 38 分钟车程——你自己决定" |
