# 可执行行程编排引擎 · 成都

> 华为 ICT 创新赛（2026—2027）赛题一「基于华为云产品打造 AI 创新应用」参赛原型

小红书给地点，高德给单段路线。这个项目做中间那一层：
**把用户勾选的景点，排成一份真的走得完的行程**——每个点几点到、待多久、坐几号线、
从哪个口出、换几路公交、在哪站下、走多少米、几点收工。

## 现在能跑什么

| 能力 | 说明 |
|---|---|
| 需求 → 行程 | 天数 / 同行人 / 节奏 / 预算 / 出发日，改任一参数立刻重排，约 12 ms |
| 选点即算代价 | 勾一个景点，返回交通 +34 分钟、步行 +1.3 km、车费 +4 元，约 5 ms |
| 出口级描述 | 「2 号线往一品天下方向 2 站 → 从 B 口出站，步行 150 米」 |
| 时间上真的可行 | 独立校验器重推时间轴，0 违规；30 组随机输入同样 0 违规 |
| 排不下会说实话 | 不硬塞，明确说「杜甫草堂排不进第 1 天，要么加半天，要么换同区域低分点」 |
| 扰动只改局部 | 某天下雨只重排那天，其余天一个点都不动 |

## 快速开始

```bash
cd prototype
python serve.py                 # 打开 http://127.0.0.1:8765
python serve.py --host 0.0.0.0  # 手机同一 WiFi：http://<你的电脑IP>:8765
```

命令行演示与测试：

```bash
python run_demo.py                                # 六个演示：生成 / 校验 / 边际成本 / 重排 / 压测 / 接口示例
python -m unittest discover -s tests -t . -v      # 5 条回归测试
```

只依赖 Python 标准库，不用装任何包。

## 它是怎么分层的

```
web/（单页前端，无框架）        ← 手机 / 电脑自适应
      │  HTTP / JSON
serve.py（标准库 http.server）
      │
planner.py（编排层）─── transit.py（事实层：步行/地铁/公交/出口）
      │                     ↑ 待替换为高德公交路径规划 API
      ├── validator.py（独立校验：重推时间轴）
      └── explain.py（表达层）  ↑ 待替换为华为云 MaaS
```

一句话原则：**地图 API 是事实，求解器是决策，LLM 是表达，三者不能互换。**
大模型只负责听懂人话和说人话，单段路怎么走必须来自地图接口，一天怎么排必须来自约束求解。

## 技术取舍

- **时间全部用整数分钟**（`09:00` → `540`），避免 datetime 和时区把编排逻辑搅乱。
- **先可行再最优**：开放时间、闭馆日、最短停留、午餐窗、每日结束、步行上限、预算都是硬约束；
  排不下按满意度从低到高舍弃，并且把舍弃原因写给用户看。
- **增量重算**：勾选一个点只做插入/替换，不动其余天，所以能做到 5 ms 返回。
- **独立校验**：校验器不复用编排器的判断，从 09:00 重推一遍时间轴；测试里还会故意改坏一条行程，
  确认校验器真的能抓到。

## 数据说明

成都地铁 1/2/3/4/7 号线骨架、`1024路（示意）`、出口距离均为**示意数据**，用于验证算法与交互；
景点开放时间/票价按公开信息整理。接入真实地图开放平台后，只需替换 `engine/providers/transit.py`
的 `route()`，调用方无需改动。
